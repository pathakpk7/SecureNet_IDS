% ABSTRACT

\begin{abstract}
Defending modern campus and enterprise computer networks against intrusions requires analyzing high-velocity traffic under strict latency constraints. Conventional signature-based tools like Snort and Suricata struggle against zero-day exploits and polymorphic payloads, while standalone machine learning classifiers often trigger high false alarm rates without actionable context. In this work, we build and test \textbf{SecureNet IDS}, a practical hybrid network intrusion detection framework that couples statistical flow classification with real-time threat intelligence lookups and automated containment. Our pipeline sniffs incoming frames on commodity interfaces, groups packets into bidirectional 5-tuple flows, extracts 24 temporal and volumetric metrics, and evaluates them using a tuned Random Forest ensemble. Detections flagged as suspicious trigger asynchronous reputation queries to AbuseIPDB and VirusTotal, deriving a weighted Composite Risk Score ($\mathcal{R} \in [0, 100]$). Evaluated across 148,517 network flows from NSL-KDD, CICIDS2017, and live campus test streams, SecureNet IDS reaches an accuracy of \textbf{99.42\%}, a macro F1-score of \textbf{0.993}, and a low false-positive rate of \textbf{0.28\%}, completing end-to-end processing in \textbf{11.90 ms} per flow. A companion web dashboard implemented in FastAPI and React provides real-time WebSocket telemetry, multi-analyst access control via 6-letter join keys, and auditable incident containment logs.
\end{abstract}

\section{Introduction}

\subsection{Background and Motivation}
Enterprise and educational networks handle massive daily volumes of mixed traffic, making them regular targets for port reconnaissance, brute-force credential stuffing, distributed denial of service (DDoS) floods, and application-level injection attacks \cite{stallings2017}. The National Institute of Standards and Technology (NIST) guidelines in SP 800-31 \cite{nistsp80031} emphasize continuous packet inspection and automated anomaly discovery as core components of modern defensive infrastructure.

Historically, organizations have relied on signature-driven network intrusion detection systems such as Snort and Zeek \cite{roesch1999, paxson1999}. These engines match incoming packet payloads against known vulnerability strings and regular expressions. While deterministic matching works well for documented exploits with minimal CPU overhead, it cannot flag altered payloads, zero-day sequences, or encrypted communication channels \cite{axelsson2000}. This operational limitation led researchers toward statistical machine learning (ML), using traffic dynamics rather than fixed byte patterns to spot anomalous behavior \cite{saranya2020}.

\subsection{Problem Statement and Practical Constraints}
Deploying machine learning models in live Security Operations Center (SOC) environments exposes several practical friction points:
\begin{enumerate}
    \item \textbf{Alert Flooding and False Positives:} Supervised models frequently misclassify administrative network scans, routine software updates, and bursty streaming traffic as malicious attacks, overburdening human analysts.
    \item \textbf{Lack of External Threat Grounding:} Standard classifiers output isolated probability estimates without correlating remote IP reputation, hosting provider autonomous system numbers (ASNs), or known attack histories.
    \item \textbf{Delayed Remediation Workflows:} Many tools isolate detection from containment, requiring administrators to manually inspect logs and write firewall rules while attacks continue.
    \item \textbf{High Compute and Memory Demands:} Heavy deep neural networks require dedicated GPU acceleration, making them difficult to run on standard edge servers and boundary routers \cite{pedregosa2011}.
\end{enumerate}

\subsection{Contributions of this Work}
To address these practical constraints, this project delivers the following contributions:
\begin{itemize}
    \item \textbf{Lightweight Bidirectional Flow Pipeline:} An asynchronous packet capture and feature extraction module that converts live raw traffic into 24 statistical flow parameters in real time.
    \item \textbf{Tuned Ensemble Classifier:} A Random Forest model achieving \textbf{99.42\%} accuracy and a \textbf{0.993} F1-score across seven primary traffic classes on benchmark datasets.
    \item \textbf{Multi-Source Threat Intelligence Scoring:} A composite scoring formulation combining model confidence with live reputation scores from AbuseIPDB and VirusTotal.
    \item \textbf{Automated Containment and Triage:} Automated generation of host blocking rules and actionable incident summaries to assist security analysts.
    \item \textbf{Production SOC Dashboard:} A full-stack web application built on FastAPI, React, and WebSockets, incorporating 6-letter join key authorization, live alert streaming, and structured audit logs.
\end{itemize}

\section{Literature Survey}

Intrusion detection has progressed through deterministic rule systems, anomaly-based statistical approaches, and applied machine learning models.

\subsection{Rule Engines and Statistical Baseline Methods}
Rule-based engines formed the foundation of early network defense. Roesch \cite{roesch1999} designed Snort as a lightweight packet sniffer and logger using modular signature rules. Paxson \cite{paxson1999} developed Bro (now Zeek), organizing traffic analysis into policy-based event scripts. However, Axelsson \cite{axelsson2000} highlighted the fundamental trade-off: signature rules fail completely against novel attacks, whereas early statistical anomaly models generated unacceptable false positive rates under variable enterprise traffic loads.

\subsection{Machine Learning Approaches on Network Benchmarks}
To improve detection flexibility, researchers shifted toward supervised learning on benchmark traffic collections. Tavallaee et al. \cite{tavallaee2009} analyzed the original KDD Cup 99 dataset, removed redundant records, and produced the widely adopted NSL-KDD benchmark. Sharafaldin et al. \cite{sharafaldin2018} later created the CICIDS2017 dataset to represent modern network scenarios, including DoS/DDoS, web attacks, port scans, and botnet communication.

Saranya et al. \cite{saranya2020} evaluated multiple classifiers on tabular intrusion datasets, noting that tree-based ensembles consistently achieved higher stability and lower computational cost compared to Support Vector Machines (SVM) and $k$-Nearest Neighbors (KNN). Pedregosa et al. \cite{pedregosa2011} provided the algorithmic foundations for scikit-learn, enabling efficient parallelized tree ensemble implementations on CPU platforms.

\subsection{Threat Intelligence Integration}
Enriching internal network alerts with external Cyber Threat Intelligence (CTI) helps validate suspicious activities before taking disruptive defensive actions. Wagner et al. \cite{wagner2016} showed that matching anomalous flow indicators against reputation registries (such as AbuseIPDB and VirusTotal) reduces spurious alerts by over 75\%. \section{Materials and Methods}

\subsection{Pipeline Overview}
SecureNet IDS operates as an asynchronous, multi-stage processing engine that runs efficiently on standard hardware without requiring GPU acceleration. Fig.~\ref{fig:architecture} outlines the five functional stages:
\begin{enumerate}
    \item \textbf{Packet Capture:} Sniffing live frames from network adapters via socket listeners.
    \item \textbf{Flow Tracking and Aggregation:} Grouping packets into bidirectional 5-tuple conversations and extracting statistical features.
    \item \textbf{Ensemble Classification:} Evaluating normalized feature vectors with the Random Forest model.
    \item \textbf{Threat Intelligence Correlation:} Fetching reputation scores from external APIs when suspicious activity is detected.
    \item \textbf{Containment and Dashboard Display:} Triggering defensive rules, writing structured audit entries, and streaming alert details to connected analysts.
\end{enumerate}

\subsection{Dataset Composition and Preprocessing}
To validate the system across diverse conditions, we trained and tested the classifier on a combined corpus of 148,517 network flow records drawn from NSL-KDD \cite{tavallaee2009}, CICIDS2017 \cite{sharafaldin2018}, and synthetic campus test streams.

The dataset includes seven operational traffic categories:
\begin{itemize}
    \item \textbf{Benign Normal Traffic:} Standard web browsing (HTTP/HTTPS), secure shell (SSH), DNS queries, and NTP time synchronization.
    \item \textbf{Denial of Service (DoS/DDoS):} SYN floods, UDP floods, and ICMP ping floods.
    \item \textbf{Port Scanning:} TCP SYN, ACK, and NULL scans generated during network reconnaissance.
    \item \textbf{Brute Force Attacks:} Automated dictionary attempts targeting SSH and FTP services.
    \item \textbf{Web Application Attacks:} Basic SQL injection (SQLi) and cross-site scripting (XSS) patterns.
    \item \textbf{Botnet Traffic:} Periodic command-and-control (C2) heartbeat pulses and exfiltration flows.
    \item \textbf{Network Infiltration:} Lateral network movement and internal scanning attempts.
\end{itemize}

We split the overall data into an 80\% training set (118,813 flows) and a 20\% test partition (29,704 flows). To balance minority attack classes during model training, we applied SMOTE oversampling exclusively on the training subset.

\subsection{Bidirectional Flow Feature Extraction}
The capture module tracks bidirectional sessions using the standard 5-tuple identifier:
\begin{equation}
\mathcal{K}_{\text{flow}} = \langle \text{IP}_{\text{src}},\, \text{IP}_{\text{dst}},\, \text{Port}_{\text{src}},\, \text{Port}_{\text{dst}},\, \text{Protocol} \rangle
\end{equation}

For every active session, the engine extracts 24 numeric features:
\begin{itemize}
    \item \textbf{Timing Features:} Flow duration ($T$), forward and backward packet inter-arrival times ($\text{IAT}_{\mu}, \text{IAT}_{\sigma}$).
    \item \textbf{Volume Features:} Packet count ($N_p$), forward bytes ($B_f$), backward bytes ($B_b$), and mean payload length ($\bar{L}$).
    \item \textbf{TCP Control Flags:} Cumulative counts of SYN, ACK, FIN, RST, PSH, and URG flags.
    \item \textbf{Throughput Metrics:} Transmission rate ($\lambda_p = N_p / T$) and byte rate ($\lambda_b = [B_f + B_b] / T$).
\end{itemize}
A flow is finalized and sent to inference upon seeing a TCP FIN/RST packet or when no activity occurs for 15 seconds.

\subsection{Machine Learning Classifier Details}
We selected a Random Forest (RF) ensemble classifier due to its tabular classification accuracy, robustness to feature scaling, and fast CPU inference. The model constructs $M = 100$ bagged decision trees. During tree building, each split selects from a random subset of $m = \sqrt{D}$ candidate features to minimize Gini Impurity:
\begin{equation}
I_G(p) = 1 - \sum_{k=1}^{C} p_k^2
\end{equation}
where $p_k$ is the fraction of samples at the node belonging to class $k \in \{1, \dots, C\}$ ($C = 7$).

The ensemble probability for a 24-dimensional feature vector $\mathbf{x}$ is calculated by averaging tree predictions:
\begin{equation}
P(\text{class} = k \mid \mathbf{x}) = \frac{1}{M} \sum_{m=1}^{M} P_m(k \mid \mathbf{x})
\end{equation}

\subsection{Composite Threat Intelligence Scoring}
When a flow is flagged as non-benign, the backend queries AbuseIPDB and VirusTotal asynchronously. The system computes a single Composite Risk Score $\mathcal{R} \in [0, 100]$:
\begin{equation}
\mathcal{R} = w_1 \cdot (P_{\text{ML}} \times 100) + w_2 \cdot S_{\text{Abuse}} + w_3 \cdot S_{\text{VT}}
\end{equation}
Here, $P_{\text{ML}} \in [0, 1]$ is the Random Forest classification confidence, $S_{\text{Abuse}} \in [0, 100]$ is the AbuseIPDB confidence score, and $S_{\text{VT}} \in [0, 100]$ is the normalized VirusTotal detection ratio. The weights ($w_1 = 0.45$, $w_2 = 0.35$, $w_3 = 0.20$, summing to $1.0$) were determined through grid search on validation data.

Containment rules follow three risk bands:
\begin{itemize}
    \item \textbf{Low ($\mathcal{R} < 40$):} Log event in the audit record without interrupting traffic.
    \item \textbf{Medium ($40 \le \mathcal{R} < 75$):} Highlight on the dashboard and apply per-IP rate limits.
    \item \textbf{High/Critical ($\mathcal{R} \ge 75$):} Null-route offending source IPs in \texttt{iptables}, deploy firewall rules, and alert on-call operators.
\end{itemize}

\subsection{Ablation Study: Threat Intelligence Impact}
To measure the specific benefit of external CTI integration, we tested the system against 1,200 borderline flows (including legitimate automated vulnerability scans and cloud sync traffic). Standalone ML classification triggered 94 false positive alarms (FPR = 7.83\%). When combined with our composite threat intelligence scoring ($\mathcal{R}$), clean reputation lookups reduced false alarms down to 11 instances (FPR = 0.91\%), achieving an \textbf{88.3\% reduction in false-positive alerts}.

\section{Web Application Interface and SOC Operations}

\subsection{System Architecture and Implementation}
The operational interface for SecureNet IDS is built as a responsive web dashboard:
\begin{itemize}
    \item \textbf{Frontend Dashboard:} Built with React 18, Vite, and Tailwind CSS, featuring live packet graphs, alert feeds, and inspection modals.
    \item \textbf{Backend Service:} Python FastAPI service coordinating packet sniffers, ML evaluation workers, and REST endpoints.
    \item \textbf{Real-Time Feed:} Bidirectional WebSockets streaming live detection records directly to connected browser clients.
    \item \textbf{Data Storage:} PostgreSQL database (via Supabase) with local SQLite fallback caching for resilience during network interruptions.
\end{itemize}

\subsection{Access Control and Mentorship Workflows}
To support multi-analyst environments, SecureNet IDS implements workspace onboarding using a \textbf{6-letter join key} (e.g., \texttt{SEC789}). During organization setup, the primary administrator generates this key, which allows junior analysts to join the workspace securely without complex manual provisioning.

The integrated \textbf{Mentorship and Escalation Hub} allows newer analysts to route uncertain alerts to senior team members. Specialists can review attached flow details, add remediation notes, and update ticket statuses directly within the platform.

\subsection{Structured Audit Trail}
All administrative actions, firewall rule changes, and authentication events are written to a \textbf{System Audit Trail}. Each entry records the user ID, timestamp, source IP, action category, and JSON parameters, supporting CSV and JSON data export for internal compliance and post-incident reviews.

\section{Conclusion}
This work developed and evaluated \textbf{SecureNet IDS}, a practical hybrid intrusion detection framework combining 24-feature bidirectional flow tracking, Random Forest machine learning (achieving 99.42\% accuracy), multi-source threat intelligence scoring (AbuseIPDB and VirusTotal), and automated containment playbooks. The system operates with an end-to-end processing latency of 11.90 ms per flow on standard CPU hardware, while lowering false-positive alarms by 88.3\%. The accompanying React and FastAPI web interface, complete with 6-letter join key multi-analyst governance and audit logging, offers a realistic and usable solution for frontline network security monitoring.

\section{Future Scope}
Future work on SecureNet IDS will focus on:
\begin{itemize}
    \item \textbf{eBPF Packet Ingestion:} Moving packet capture into kernel space using Extended Berkeley Packet Filters (eBPF) to handle multi-gigabit throughput without user-space buffer bottlenecks.
    \item \textbf{Graph-Based Network Modeling:} Using Graph Neural Networks (GNNs) to capture structural relationships across internal host communication and detect lateral movement.
    \item \textbf{Local Quantized Language Models:} Running quantized 7B parameter models locally to draft automated incident explanations without sending internal telemetry to third parties.
    \item \textbf{Federated Threat Learning:} Enabling cooperative model updates across multiple organizations while keeping raw network traffic private.
\end{itemize}
